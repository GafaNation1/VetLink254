# VetLink254 — Documentation Index

Read in this order:

1. **`CURRENT_STATE.md`** — the authoritative, up-to-date reference: the real folder tree, what
   actually works right now (with exact commands), what's stubbed / not built, how to run
   everything from scratch, honest known limitations, and next steps. **Start here.**
2. **`DEPLOYMENT_CREDENTIALS.md`** — the exhaustive real-world credentials checklist (Render,
   Africa's Talking, Cloudflare R2, KVB, domain/DNS): every variable name, exact file/section that
   reads it, where to obtain it, and required-vs-optional. **Read this when you are ready to go live.**
3. **`KVB_INTEGRATION.md`** — the technical contract between VetLink254 and the Kenya Veterinary
   Board (what VetLink254 needs from KVB, what it explicitly does not ask for).
4. **`architecture.md`** — the original product vision and engineering blueprint (the "what we're
   building and why"). Design sections are referenced throughout `progress/LOG.md`.
5. **`progress/STATUS.md`** — living one-glance snapshot: what's built / what's next / what's broken.
6. **`progress/LOG.md`** — append-only, session-by-session build history (every file created,
   every decision made, every gap logged). Add to it at the end of every session per `AGENT_PROTOCOL.md`.

**`AGENT_PROTOCOL.md`** (repo root) is the rulebook every agent must follow — read it first too.
